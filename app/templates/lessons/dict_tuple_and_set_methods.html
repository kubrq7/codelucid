02. Python Core Reference Unit - Dictionary, Tuple, & Set Methods

An advanced technical reference explaining structural data mutation, lookup limits, and mathematical set architectures within Python's built-in collections.

1. Dictionary Key-Value Management

Academic Overview:

  • Hash Table Mechanics: Python dictionaries leverage internal hash tables to guarantee $O(1)$ amortized time complexity for insertion, deletion, and key lookups.
  • Defensive Lookup: Accessing missing keys using bracket syntax (dict[key]) raises a KeyError, whereas .get() provides a graceful fallback value without disrupting execution threads.
  • Dynamic View Objects: Methods like .keys(), .values(), and .items() yield dynamic, read-only view structures that immediately mirror changes made to the underlying dictionary data.
print("--- Section 1: Dictionary Operations ---")

user_profile = {
    "username": "kubra_dev",
    "role": "Engineer",
    "status": "Active"
}

# 1. Safe Access via get() - prevents KeyError if key does not exist
role_value = user_profile.get("role", "Guest")
location_value = user_profile.get("location", "Not Specified")
print(f"[Get] Role: {role_value} | Location: {location_value}")

# 2. Extracting Structural Views (Keys, Values, and Items)
print(f"[Keys] View Object: {list(user_profile.keys())}")
print(f"[Values] View Object: {list(user_profile.values())}")
print(f"[Items] Key-Value Pairs: {list(user_profile.items())}")

# 3. Mutation and Update Operations
user_profile.update({"status": "In-Break", "experience": "Python Master"})
print(f"[Update] Mutated Profile: {user_profile}")

# 4. Pop & Popitem: Explicit removal mechanics
removed_status = user_profile.pop("status")
print(f"[Pop] Removed Value: {removed_status} | Current Dict: {user_profile}")

# Removes and returns the last inserted key-value pair as a tuple
last_inserted = user_profile.popitem()
print(f"[Popitem] Removed Last Entry: {last_inserted}\n")

2. Tuple Immutability Verification

Academic Overview:

  • Fixed Allocations: Tuples are strictly immutable, fixed-size linear sequences. Because their structure cannot change after instantiation, they require less memory than lists and are optimized for read-only tracking.
  • Methods Restriction: Due to their write-protected design, tuples expose only two data lookup methods: .count() and .index().
print("--- Section 2: Tuple Operations ---")

# Tuples are immutable data streams - only two standard lookup methods exist
immutable_coordinates = (10, 20, 30, 20, 40, 20)

# 1. Count: Tallies occurrences of a target structural element
twenty_count = immutable_coordinates.count(20)
print(f"[Count] Occurrences of value 20: {twenty_count}")

# 2. Index: Searches for a value and returns its first index position
position_of_thirty = immutable_coordinates.index(30)
print(f"[Index] First position index of value 30: {position_of_thirty}\n")

3. Set Mathematical Operations

Academic Overview:

  • Unordered Uniqueness: Sets are unordered collections of distinct, hashable items. They enforce uniqueness by filtering out duplicate values automatically upon insertion.
  • Algebraic Operations: Highly optimized operations handle mathematical relations directly in engine memory:
    • Intersection: Yields elements shared across both domains ($A \cap B$).
    • Union: Blends sets together while omitting overlapping duplicates ($A \cup B$).
    • Difference: Extracts items exclusive to the caller container ($A \setminus B$).
  • Safe Mutations: While .remove() triggers a KeyError if an element is missing, .discard() provides an elegant, safe removal interface that bypasses exceptions.
print("--- Section 3: Set Operations ---")

# Sets hold unique, unordered elements
backend_stack = {"Python", "MongoDB", "MySQL", "FastAPI"}
frontend_stack = {"HTML", "CSS", "JavaScript", "Python"}

# 1. Intersection: Elements present in BOTH sets
common_skills = backend_stack.intersection(frontend_stack)
print(f"[Intersection] Common Core Elements: {common_skills}")

# 2. Union: Combined elements from BOTH sets (duplicates automatically removed)
all_skills = backend_stack.union(frontend_stack)
print(f"[Union] Complete Aggregated Stack: {all_skills}")

# 3. Difference: Elements in backend_stack that are NOT in frontend_stack
exclusive_backend = backend_stack.difference(frontend_stack)
print(f"[Difference] Exclusive Backend Core: {exclusive_backend}")

# 4. Element Manipulation (Add / Discard)
backend_stack.add("Django")
print(f"[Add] Mutated Set State: {backend_stack}")

# discard() is safer than remove() because it does not throw an error if item is missing
backend_stack.discard("Flask") 
print("[Discard] Non-destructive removal operation verified.")

print("\n[SUCCESS] Dictionary, Tuple, and Set reference engines evaluated cleanly.")
