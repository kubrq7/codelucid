02. Python Backend Unit - MySQL Operations

A rigorous academic and implementation roadmap exploring relational database engineering via Python using the official mysql-connector-python driver engine.

import mysql.connector

1. Connection Setup & Database Creation

Academic Overview:

  • Server Initialization: Establishes a persistent TCP/IP network handshake with the host engine over the default service port.
  • State Persistence: Instantiates isolated query workspace cursors tasked with executing consecutive data definition operations.
print("--- Section 1: Connection & Database Setup ---")

# Establishing structural connection to local MySQL server host
db_connection = mysql.connector.connect(
    host="localhost",
    user="root",
    password="your_secure_password"
)

db_cursor = db_connection.cursor()

# Creating a fresh isolated database instance
db_cursor.execute("CREATE DATABASE IF NOT EXISTS commerce_system")
db_cursor.execute("USE commerce_system")
print("[INFO] MySQL connection established and database initialized.\n")

2. Table Creation (Structural Framework)

Academic Overview:

  • Relational Schema Design: Establishes normalized tabular spaces bounding data domains to maintain operational integrity.
  • Integrity Constraints: Maps explicit PRIMARY KEY targets alongside referencing FOREIGN KEY indicators to construct rigorous parent-child cardinality relations.
print("--- Section 2: Table Creation Phase ---")

# Creating 'categories' table to establish relationship mapping later
db_cursor.execute("""
    CREATE TABLE IF NOT EXISTS categories (
        category_id INT AUTO_INCREMENT PRIMARY KEY,
        category_name VARCHAR(255) NOT NULL
    )
""")

# Creating 'products' table with a relational Foreign Key setup
db_cursor.execute("""
    CREATE TABLE IF NOT EXISTS products (
        product_id INT AUTO_INCREMENT PRIMARY KEY,
        name VARCHAR(255) NOT NULL,
        price DECIMAL(10, 2) NOT NULL,
        stock INT DEFAULT 0,
        category_id INT,
        FOREIGN KEY (category_id) REFERENCES categories(category_id)
    )
""")
print("[INFO] Relational schema layout built successfully.\n")

3. Data Insertion Mechanics (Create)

Academic Overview:

  • Parameterized Directives: Utilizes explicit token strings (%s) to escape data payloads, immunizing the core execution engine from destructive SQL injection attacks.
  • Transaction Control: Explicitly implements .commit() invocations to flush cached buffer alterations into physical system disk clusters, satisfying ACID reliability requirements.
print("--- Section 3: Data Insertion Operations ---")

# 1. Populating the categories table first
category_query = "INSERT INTO categories (category_name) VALUES (%s)"
categories_data = [("Electronics",), ("Furniture",)]
db_cursor.executemany(category_query, categories_data)
db_connection.commit()  # Committing the transactions permanently

# 2. Populating the products table (Insert One & Insert Many)
product_query = "INSERT INTO products (name, price, stock, category_id) VALUES (%s, %s, %s, %s)"

# Single insertion demonstration
db_cursor.execute(product_query, ("Wireless Mouse", 850.00, 120, 1))

# Bulk insertion optimization
bulk_products_data = [
    ("Mechanical Keyboard", 2400.00, 45, 1),
    ("Gaming Monitor", 6200.00, 15, 1),
    ("Ergonomic Chair", 4500.00, 8, 2),
    ("Office Desk", 3800.00, 12, 2)
]
db_cursor.executemany(product_query, bulk_products_data)
db_connection.commit()
print(f"[Insert] Row count affected: {db_cursor.rowcount} entries saved.\n")

4. Query Evaluation & Restrictions (Read)

Academic Overview:

  • Query Execution Pipeline: Projects tabular matrices across complex data channels by chaining conditional filtering, ordering vectors, and limit windows directly within the database optimizer.
print("--- Section 4: Querying, Filtering, and Sorting Data ---")

# Utilizing SELECT, WHERE, ORDER BY, and LIMIT in a cohesive query pipeline
advanced_query = """
    SELECT name, price, stock 
    FROM products 
    WHERE price > %s 
    ORDER BY price DESC 
    LIMIT %s
"""
db_cursor.execute(advanced_query, (2000.00, 2))
query_results = db_cursor.fetchall()

print("[Query Results] Filtered Evaluation Profile (Price > 2000, Limit 2):")
for row in query_results:
    print(f" - Product: {row[0]} | Price: {row[1]} TRY | Available Stock: {row[2]}")
print("")

5. Data Modification & Deletion (Update & Delete)

Academic Overview:

  • Mutation Safety: Performs state alterations on precise targets using rigid WHERE filtering boundaries to guarantee that changes do not affect unintended rows.
print("--- Section 5: Modification and Deletion Tasks ---")

# Executing an explicit UPDATE query to alter active records
update_query = "UPDATE products SET price = %s WHERE name = %s"
db_cursor.execute(update_query, (950.00, "Wireless Mouse"))
db_connection.commit()
print("[Update] 'Wireless Mouse' pricing matrices adjusted.")

# Executing a row-level DELETE query safely with parameters
delete_query = "DELETE FROM products WHERE stock = %s"
db_cursor.execute(delete_query, (0,))  # Deletes products that are out of stock
db_connection.commit()
print("[Delete] Out-of-stock data purge query executed.\n")

6. Advanced SQL Join Operation (Relational Linking)

Academic Overview:

  • Inner Join Mechanics: Combines distinct tabular entities into a unified virtual projection by resolving matching keys across table dimensions.
print("--- Section 6: Relational Joining Layer (INNER JOIN) ---")

# Connecting tables using explicit relational intersection keys
join_query = """
    SELECT p.name, p.price, c.category_name 
    FROM products p
    INNER JOIN categories c ON p.category_id = c.category_id
"""
db_cursor.execute(join_query)
join_results = db_cursor.fetchall()

print("[Join Results] Unified Product-Category Data View:")
for record in join_results:
    print(f" - Item Name: {record[0]} | Price: {record[1]} TRY | Sub-Category: {record[2]}")
print("")

7. Cleanup & Structural Deconstruction

Academic Overview:

  • Resource Deallocation: Safely closes cursors and connection pipelines to prevent memory leaks or exhausting database connection pools.
  • Referential Drop Sequences: Drops dependent child tables before parent tables to cleanly dismantle entities without violating foreign key constraints.
print("--- Section 7: Destructive Cleanup Phase ---")

# Dropping tables sequentially to preserve foreign key constraints
db_cursor.execute("DROP TABLE IF EXISTS products")
db_cursor.execute("DROP TABLE IF EXISTS categories")
print("[Drop] Tables truncated and structural space cleaned up.")

# Close connection resources cleanly
db_cursor.close()
db_connection.close()
print("\n[SUCCESS] All MySQL operational modules finished with 100% data fidelity.")
